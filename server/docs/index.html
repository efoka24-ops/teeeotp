API OTP et SMS

Envoyez des codes de verification et des notifications par SMS a vos utilisateurs au Cameroun, avec une API HTTP simple. Le code est genere et verifie par teeeotp : votre application ne le manipule jamais.

URL de base : https://trugroup.cm/teeeotp

Demarrage rapide

  1. Demandez un acces. Apres validation, vous recuperez une cle de test sk_test_… sur votre page de suivi.
  2. Placez-la dans la configuration de votre serveur : TEEEOTP_API_KEY=sk_test_…
  3. Envoyez un code, puis verifiez celui que l'utilisateur a saisi :
curl -X POST https://trugroup.cm/teeeotp/v1/otp/send \
  -H "X-Api-Key: $TEEEOTP_API_KEY" -H "Content-Type: application/json" \
  -d '{"phone":"690000000","purpose":"signup"}'

# → {"requestId":"9b2f…","expiresIn":300,"status":"queued","test":true,"testCode":"482913", …}

curl -X POST https://trugroup.cm/teeeotp/v1/otp/verify \
  -H "X-Api-Key: $TEEEOTP_API_KEY" -H "Content-Type: application/json" \
  -d '{"requestId":"9b2f…","code":"482913"}'

# → {"valid":true,"phone":"+237690000000","purpose":"signup"}

C'est tout. Le parcours complet : votre serveur demande un code et garde le requestId (en session) ; l'utilisateur recoit le SMS et saisit le code ; votre serveur demande a teeeotp si ce code est le bon.

Authentification

Chaque appel porte la cle de votre projet dans l'en-tete X-Api-Key (ou Authorization: Bearer …).

La cle ne doit jamais quitter votre serveur. N'appelez pas l'API depuis une application mobile ou une page web : la cle y serait lisible par n'importe qui, qui pourrait alors envoyer des SMS a vos frais. Votre application appelle votre serveur, qui appelle teeeotp.

Les corps de requete et de reponse sont en JSON (Content-Type: application/json).

Mode test

Deux sortes de cles existent :

CleUsageEnvoi
sk_test_…Developpement, recette, tests automatisesQuelques vrais SMS (5 par defaut), puis simulation : l'appel reussit, rien ne part.
sk_live_…ProductionTous les SMS partent, dans la limite du quota journalier du projet.

Avec une cle de test, les reponses contiennent en plus :

  • "test": true
  • "testCode" : le code envoye, pour que vos tests automatises puissent le verifier sans lire de SMS ;
  • "testSmsRemaining" : le nombre de vrais SMS d'essai restants ;
  • "status": "simulated" une fois l'allocation epuisee (au lieu de "queued").

La verification (/v1/otp/verify) fonctionne de la meme facon dans les deux modes. Passer en production revient a changer la cle dans votre configuration : aucune ligne de code ne change.

Reference

POST/v1/otp/send — envoyer un code
ChampTypeDescription
phonetexte, requisMobile camerounais : 690000000, 237690000000 ou +237690000000.
purposetexteMotif libre (signup, login, reset…), 30 caracteres max. Defaut : verification.
lengthentierNombre de chiffres, de 4 a 8. Defaut : 6.

Reponse 202 :

{ "requestId": "9b2f1c0e-…", "expiresIn": 300, "length": 6, "status": "queued" }

Le SMS recu : « 482913 est votre code MonProjet. Valide 5 min. Ne le partagez avec personne. » Le code en tete permet le remplissage automatique sur Android et iOS.

ChampTypeDescription
requestIdtexte, requisRenvoye par /v1/otp/send.

Reponse 200, toujours, que le code soit bon ou non :

{ "valid": true, "phone": "+237690000000", "purpose": "signup" }
{ "valid": false, "reason": "invalid_code", "attemptsLeft": 4 }
reasonQue faire
invalid_codeAfficher « code incorrect » et le nombre d'essais restants.

already_usedCode deja valide une fois : il ne sert pas deux fois.
not_foundrequestId inconnu (ou d'un autre projet).
GET/v1/otp/{requestId} — etat d'un code

Utile pour afficher « SMS envoye » ou diagnostiquer un code jamais recu.

{ "requestId": "9b2f…", "status": "pending", "attemptsLeft": 5, "expiresAt": "2026-10-20T10:05:00.000Z",
  "sms": { "status": "delivered", "sentAt": "…", "deliveredAt": "…", "error": null } }

sms.status : queued (en file), sending, sent (accepte par le reseau), delivered (recu), failed, expired (non parti a temps : un code n'est jamais envoye en retard), simulated (mode test).

Erreurs

Toute erreur a la meme forme, avec un statut HTTP 4xx ou 5xx :

{ "error": { "code": "INVALID_PHONE", "message": "phone doit etre un mobile camerounais…" } }
HTTPcodeCause
400INVALID_PHONENumero qui n'est pas un mobile camerounais.
400INVALID_REQUESTChamp manquant ou mal forme.
401UNAUTHORIZEDCle absente, invalide, revoquee, ou projet suspendu.
404NOT_FOUNDRoute inconnue (prefixe /v1 ?) ou ressource d'un autre projet.
429TOO_MANY_REQUESTSTrop de codes pour ce numero. Champ retryAfter en secondes.
429QUOTA_EXCEEDEDQuota journalier du projet atteint.
5xxINTERNAL_ERROR, SERVICE_UNAVAILABLEIncident de notre cote : reessayez plus tard.

Limites

  • Par numero : 3 codes par tranche de 15 minutes en production (10 en test, par projet).
  • Par code : valide 5 minutes, 5 essais au plus.
  • Par projet : quota de SMS par jour, fixe a l'ouverture de l'acces.
  • Numeros : mobiles camerounais uniquement (+237 6XX XX XX XX).
  • Expediteur : les SMS partent d'un numero de telephone, pas d'un nom de marque. Votre nom figure dans le texte du message.

Bonnes pratiques

  • Gardez la cle cote serveur, dans une variable d'environnement, jamais dans un depot Git.
  • Conservez le requestId en session serveur, pas dans un champ cache du formulaire.
  • Proposez « renvoyer le code » apres 60 secondes, pas avant : chaque demande compte dans la limite par numero.
  • Traitez 429 en affichant le delai (retryAfter) plutot qu'une erreur generique.
  • N'affichez pas « code envoye par SMS » si l'appel a echoue : l'utilisateur chercherait un SMS qui n'existe pas.
  • Utilisez votre cle de test en developpement et en recette, la cle de production uniquement sur le serveur de production.

Client PHP

Un seul fichier, sans dependance (extension curl) : telecharger TeeeOtpClient.php.

require 'TeeeOtpClient.php';
$otp = new TeeeOtpClient('https://trugroup.cm/teeeotp', getenv('TEEEOTP_API_KEY'));

try {
    $r = $otp->sendOtp($_POST['phone'], 'signup');
    $_SESSION['otp_request_id'] = $r['requestId'];
} catch (TeeeOtpException $e) {
    // $e->errorCode : INVALID_PHONE, TOO_MANY_REQUESTS ($e->retryAfter), QUOTA_EXCEEDED, UNREACHABLE…
}

$v = $otp->verifyOtp($_SESSION['otp_request_id'], $_POST['code']);
if ($v['valid']) {
    // compte verifie
}

$otp->sendSms('690000000', 'Votre commande est prete.');
const BASE = 'https://trugroup.cm/teeeotp';
const headers = { 'X-Api-Key': process.env.TEEEOTP_API_KEY, 'Content-Type': 'application/json' };

async function call(path, body) {
  const res = await fetch(BASE + path, { method: 'POST', headers, body: JSON.stringify(body) });
  const data = await res.json();
  if (!res.ok) throw Object.assign(new Error(data.error.message), { code: data.error.code });
  return data;
}

const { requestId } = await call('/v1/otp/send', { phone: '690000000', purpose: 'signup' });
const { valid } = await call('/v1/otp/verify', { requestId, code: '482913' });
